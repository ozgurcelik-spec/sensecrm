# Milestone 9A — Kabuk ve iş kuyruğu: gruplu menü, genel arama, hızlı oluştur, İş Kuyruğu, Ana Sayfa widget'ları (plan + HTTP kontratı)

Kaynak: [zoho-ekran-analizi.md](../analysis/zoho-ekran-analizi.md) ("Kabuk ve gezinme" tablosu, M9A satırı; ekran 1–2) · Kararlar: [kararlar.md](../architecture/kararlar.md) (K2, K3, K5, K7, K10, K11, K13, K14) · Önceki: [M3](m3-aktivite-rapor.md), [M6B](m6b-servis.md), [M7](m7-saas-hazirlik.md) (zorlama/kapı modülleri), [M8A](m8a-bildirimler.md) (zil), [M8C](m8c-dosya-ekleri.md) (ekler), [M8D](m8d-ozel-alanlar.md) (özel alanlar), güvenlik: [hardening-report.md](../security/hardening-report.md) · Pano kartı: `C-M9A` (dal `m9/shell`). Biçim kuralları M2–M8 ile aynı: taban yol `/api/v1`, JSON camelCase, enum'lar camelCase string, `null` alanlar yazılmaz, hatalar ProblemDetails + `code` (+ `args`, doğrulamada `errors`), sayfalı liste `{ items, page, pageSize, totalCount }` (`page` 1'den, `pageSize` varsayılan 25 / en çok 100), `sort` = `alan` veya `-alan` (bilinmeyen alan yok sayılır, her zaman kimlikle kararlı), zaman damgaları ISO 8601 UTC, gün alanları `YYYY-MM-DD`. Varsayım: M8A (zil), M8C (ekler) ve M8D (özel alanlar) `main`de birleşmiştir; bu belge onlara yalnız aşağıdaki noktalarda dokunur (§Web, §Arama sağlayıcıları, §Kapsam dışı).

**Çıktı:** Kullanıcı (1) soldaki menüde modülleri **gruplu ve daraltılabilir** (Satışlar / Aktiviteler / Envanter / Destek / Pazarlama / Ayarlar) görür; grup ve öğeler mevcut izin + plan/modül görünürlüğüyle süzülür, rozetler (geciken işler, bekleyen onaylar, SLA aşılan taleplerim) tek hafif özet uçtan gelir; (2) üst çubuktaki **"Kayıtlar ara"** kutusundan (`/` kısayolu) tüm modüllerde (firma, kişi, potansiyel, fırsat, teklif, sipariş, talep, kampanya, ürün, aktivite, dosya adı) tek istekle, **yetkisine ve planına göre** süzülmüş, Türkçe karakter/aksan duyarsız arama yapar; (3) **"+" hızlı oluştur** menüsüyle mevcut oluşturma diyaloglarını herhangi bir sayfadan açar; (4) **İş Kuyruğu** sayfasında Görevler/Toplantılar/Aramalar sekmelerini (sayaçlı, "Bugün ve Geciken" süzgeci, "6 gün geç" gösterimi) ve sol listede **sistem kuyruklarını** (bana ait potansiyeller, son 3 saatte atanan, bana ait fırsatlar, bu ay kapanan fırsatlar, dokunulmamış fırsatlar, bana ait açık talepler, SLA aşılan talepler, aktif kampanyalar, bekleyen onaylarım) ve **kullanıcı tanımlı kayıtlı kuyrukları** (özel/paylaşımlı) kullanır; (5) **Ana Sayfa**'da yeni KPI kartları, listeler ve huni grafiği görür; sıra/gizleme tercihi kişiye özeldir. Yeni **kiracı izni yoktur**; hiçbir uç başka kiracının veya okuma izni olmayan türün varlığını sızdırmaz.

## Genel arama

### Katlama işlevi ve indeks (D2)
`SearchPrimitives.EnsureAsync` (Migrator/`MigrationRunner` ve `CrmApiFactory` aynı kodu çağırır; idempotent):
```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;  CREATE EXTENSION IF NOT EXISTS unaccent;  CREATE EXTENSION IF NOT EXISTS btree_gin;
CREATE OR REPLACE FUNCTION public.crm_fold(text) RETURNS text LANGUAGE sql IMMUTABLE PARALLEL SAFE STRICT AS
$$ SELECT public.unaccent('public.unaccent'::regdictionary, lower(translate($1, 'İIıŞşĞğÜüÖöÇç', 'iiissgguuoocc'))) $$;
```
`İ/I/ı → i` **önce** `translate` ile (PostgreSQL `lower('İ')` yerel ayara bağlıdır), sonra `lower`, sonra `unaccent` (â, î, û, é…). `unaccent` `STABLE` işaretli olduğundan sarmalayıcı bilinçli `IMMUTABLE` bildirilir (`deploy/postgres/init-roles.sql`'deki `f_unaccent` ile aynı yaygın desen; sözlük sabit varsayımı belgelenir). `pg_trgm`/`unaccent` pilot init betiklerinde zaten kurulu, **`btree_gin` eklenir** (`deploy/postgres/init-roles.sql`, `infra/postgres/init.sql`; üçü de "trusted" uzantıdır, `crm_owner` yeterli; `crm_app` işlevi çağırabilir: `public` üzerinde varsayılan `EXECUTE`). Katlama **hem sütun hem sorgu tarafında aynı SQL işleviyle** yapılır (sürüklenme yok); yalnız vurgu için C# aynası vardır (aşağıda).

**Tablo başına** (her aranabilir tablonun kendi modül migration'ı, adı `AddSearchText`): gölge özellik `search_text text GENERATED ALWAYS AS (public.crm_fold(coalesce(a,'') || ' ' || coalesce(b,'') …)) STORED` (Domain'e sızmaz: `builder.Property<string>("SearchText").HasComputedColumnSql(…, stored: true)`), indeks `ix_<tablo>_search (tenant_id, search_text) USING gin (tenant_id, search_text gin_trgm_ops)` — **kiracı önce** (K3; EF: `HasIndex(x => new { x.TenantId, EF.Property<string>(x,"SearchText") }).HasMethod("gin").HasOperators(null, "gin_trgm_ops")`; `btree_gin` yoksa düz `gin (search_text gin_trgm_ops)` yedek yoludur; mimari test bu indeksleri `ix_*_search` adıyla tanır ve yedek yolda "kiracı-önce" kuralına **adlandırılmış istisna** tanır). Sütun eklemek tabloyu yeniden yazar: pilot tabloları küçüktür; büyük kiracıda bakım penceresi (runbook notu).

### Sorgu işleme
1. Girdi: `q` kırpılır, boşluk dizileri tek boşluğa, denetim karakterleri atılır; uzunluk **2–100** (aksi `validation`, `errors.q`); belirteçler boşlukla ayrılır, **ilk 5** kullanılır (belirteç ≤ 50 karakter). `%`, `_`, `\` düz metindir (`FilterExpressionBuilder.EscapeLike` yeniden kullanılır); yalnız joker karakterlerden oluşan sorgu boş sonuç döner. Desen her zaman **parametre**; dize birleştirmeyle SQL yok.
2. Koşul: `search_text LIKE public.crm_fold(@t1) AND …` (belirteç başına `%kaçışlı%`); soru işaretsiz tek sorgu.
3. **Sıralama** (sağlayıcı içinde; türler arası sıralama yok, gruplar sabit tür sırasıyla): tam başlık eşleşmesi (0) → başlık öneki (1) → kelime başı (2) → diğer (3), sonra `GREATEST(created_at, modified_date) DESC`, sonra `id`. Sıra ifadesi yalnız süzülmüş kümede hesaplanır. Tür başına `limit + 1` satır çekilir (`hasMore`).
4. Vurgu: sağlayıcılar ham `Title` döner; düzenleyici `SearchHighlighter` (C#, **1:1 karakter eşlemeli** `Fold`; SQL `crm_fold` ile Türkçe alfabe üzerinde eşdeğerlik testle sabitlenir) ile `[başlangıç, uzunluk]` aralıkları (UTF-16 birimi) üretir; eşleşme başka alandaysa (ör. e-posta) vurgu yoktur, alan içeriğe HTML **konmaz** (istemci düz metin işler, `<mark>` yalnız istemcide).
5. **Performans sınırları:** tür başına en çok 25 (varsayılan 5), sağlayıcı başına 1,5 sn komut zaman aşımı (`CommandTimeout` + iptal), toplam 2,5 sn; en çok 6 eşzamanlı bağlantı (modül sayısı); sayfalama yalnız **tek tür** seçiliyken (`page`), toplam sayı hesaplanmaz (`hasMore`). Hedef (yönerge, sıkı test değil): 50 bin kayıt/tür kiracıda p95 < 300 ms; test **plan doğrulaması** yapar (aşağıda).
6. **Hız sınırı:** yeni `RateLimitPolicyNames.Search` — kullanıcı başına 120 istek/60 sn (`RateLimiting:Search`, doğrulanmış `sub` bölümü; genel 600/dk kullanıcı + 3000/dk kiracı sınırlarına ek); aşımda `429 general.rate_limit_exceeded`. İstemci ayrıca 250 ms erteleme, en az 2 karakter ve uçuştaki isteği iptal eder.
7. **Denetim/PII:** arama okuma işlemidir, denetlenmez (mevcut ilke); günlükte yalnız `qLength`, tür listesi, tür başına sonuç sayısı, `tookMs`, `partial`. **Serilog istek günlüğü sorgu dizesini yazmaz** (yalnız `RequestPath`; testle sabitlenir); nginx `web/nginx/default.conf.template`'te `map $uri $log_search { ~^/api/v1/search$ 0; default 1; }` + `access_log … if=$log_search` (DevOps). `Referrer-Policy` mevcut (`strict-origin-when-cross-origin`; API `no-referrer`): `?q=` başka origin'e sızmaz.
8. Sağlayıcı hatası/zaman aşımı `unavailable: [{ type, reason: "timeout"|"error" }]` (hata ayrıntısı yok); tüm sağlayıcılar düşerse yine 200 + boş `groups` (istemci uyarı gösterir); iptal (istemci koptu) sessiz.

### Değiştirilebilirlik (Elasticsearch/OpenSearch, K11)

## Filtre DSL (D5) — M9B ile ortak olan ve olmayan

```json
{ "v": 1, "conditions": [ { "field": "status", "op": "in", "values": ["new","contacted"] }, { "field": "ownerUserId", "op": "eq", "values": ["@me"] }, { "field": "ownerAssignedAt", "op": "gte", "values": ["@now-3h"] } ] }
```
- **Kurallar:** ≤ 8 koşul, koşul başına ≤ 50 değer, JSON ≤ 4 KB; bilinmeyen alan, alanın tipine izin verilmeyen işleç, bozuk değer (tip ayrıştırma), bilinmeyen belirteç → `400 queue.filter_invalid` (`errors["filter.conditions[2].field"|".op"|".values"]`). Sistem kuyruklarının süzgeci de aynı biçimdedir (kodda, doğrulamadan geçer → testte tek doğruluk).
- **Tipler ve işleçler:** `enum` (camelCase anahtar) `eq ne in notin`; `guid` (kullanıcı/kayıt) `eq ne in notin` (+`isnull/notnull` yalnız boş olabilen alanda); `text` `contains startswith eq` (Türkçe katlamalı: `crm_fold(alan) LIKE …`, kaçışlı; indekssiz, kiracı-önek + diğer koşullarla daralır); `date`/`datetime` `eq gt gte lt lte between isnull notnull`; `number` `eq gt gte lt lte between`; `bool` (yalnız sanal alanlar) `eq`.
- **Belirteçler** (bağlam: kiracı saat dilimi `TenantCalendar`, kullanıcı, `TimeProvider`): `@me` (çağıran; başka kullanıcı belirteci yoktur); `@now`, `@now-<n><m|h|d>` / `@now+<n><m|h|d>` (n 1–999); `@today` ve `@tomorrow` (kiracı gününün başı: `date` alanda yerel tarih, `datetime` alanda o anın UTC'si); `@monthStart`, `@nextMonthStart` ("bu ay" = `gte @monthStart` + `lt @nextMonthStart`; yarı açık aralık `date` ve `datetime`'da aynı doğrulukta çalışır). Belirteç yalnız uyumlu tipte geçerlidir (`@me` yalnız `guid`, zaman belirteçleri yalnız `date/datetime`).
- **Sanal alanlar** (modül tarafından bir ifade fabrikası olarak kaydedilir, `bool`/`enum`): `untouched` (lead, deal), `overdue` (aktivite türleri), `slaState` (talep), `stageKind` (fırsat; aşama tablosu alt sorgusu). Derleyici bunları sütun alanlarıyla aynı çatıda çalıştırır.
- **Ortak (M9B'nin yeniden kullanacağı):** tel biçimi ve sürüm (`v`), işleç kümesi, tip/işleç kataloğu (`FilterFieldDescriptor`), belirteç sözlüğü ve çözümleyici, doğrulayıcı + derleyici (`DslFilterCompiler<T>`), sanal alan kaydı, `untouched` anlamı ve `ownerAssignedAt`/`last_activity_at` sütunları, `EscapeLike` kuralları, arayüzde **genel `FilterBuilder` bileşeni** (alan → işleç → tipe uygun girdi). **Ortak olmayan:** `SavedQueue` kalıcılığı ve paylaşım kuralı (ad, varlık, `isShared`; M9B'nin "görünüm"ü sütun/sıra/sayfa boyutu/varsayılan/rol bazlı paylaşım ekler ve kendi tablosunu açar, gerekirse kuyrukları göç ettirir), sayaç/önbellek mantığı, kuyruk sayfası. M9B alan kataloğunu genişletir (özel alan `cf.*` tanımları dinamik `FilterFieldDescriptor` üretir; **M9A kataloğunda özel alan yoktur**).

**v1 varlık katalogu** (`GET /work-queues/entities` bunu döner; kuyruk kullanıcı tanımlı olabilen varlıklar işaretli):

## Sahiplik zamanı ve "dokunulmamış" anlamı (D8, D9)

**Tanım (bağlayıcı):** Bir potansiyel/fırsat **dokunulmamış**tır ⇔ `last_activity_at IS NULL OR last_activity_at <= COALESCE(owner_assigned_at, created_at)` (sanal alan `untouched = true`; yalnız **açık** kayıtta anlamlıdır: kuyruklar ayrıca `status ∈ {new, contacted, qualified}` / `stageKind = open` ekler). Yani sayaç **sahibin değişmesiyle sıfırlanır**: A'nın aradığı fırsat B'ye atanınca B için ilk dokunuşa kadar dokunulmamıştır.
- **Dokunuş** = ilgili kayda (`relatedType/relatedId`) **kullanıcı eliyle** kaydedilmiş bir aktivite: görev, arama, toplantı veya not; **dokunuş anı** = oluşturma anı, sonradan tamamlandıysa tamamlanma anı (`COALESCE(completed_at, created_at)`; `completed_at ≥ created_at` olduğundan tamamlama da dokunuştur). **Kim yaptığı önemsizdir** (sahip olmayan meslektaş dokunuşu da sayılır); durum/aşama değişikliği, alan düzenleme, dosya eki, kampanya üyeliği dokunuş **değildir**. **Sistem/workflow** ile açılan aktiviteler sayılmaz (`created_user_id IS NULL`; `IActivityCreator` yolu olay yayınlamaz). İptal edilmiş veya sonradan silinmiş aktivite dokunuşu **geri almaz** (dokunuş gerçekleşmiştir; monoton `GREATEST`, yeniden hesap yok — bilinçli sadeleştirme, belgelenir). E-posta/çağrı sağlayıcısı yoktur (M9D/kanallar gelince yeni dokunuş türleri aynı olaya bağlanır). Karşılaştırma **katıdır**: dokunuş anı referanstan büyükse dokunulmuş, eşitse dokunulmamıştır.
- **Veri kaynağı (varlık başına):** `lead` ve `deal` — Sales'te `last_activity_at timestamptz null`; `contact`/`account` bu kartta **eklenmez** (kuyruk/widget yok; M9B genişletebilir, aynı olay). Referans: `lead.owner_assigned_at` (var, aşağıda normalleştirilir) ve `deal.owner_assigned_at` (yeni). Diğer varlıklarda (`contact`, `account`, `activity`, `case`, `campaign`) **atama zamanı yoktur**: talepte atama anı `case_events`ten türetilebilir, kuyruklarda gerekmediği için eklenmedi.
- **Olay:** `Activities.Contracts.ActivityTouched(TenantId, RelatedType, RelatedId, TouchedAt, ActorUserId)` (`IntegrationEvent`, outbox; yalnız `ActorUserId != null`, yalnız ilişkili kaydı olan aktivite; `CreateActivityCommand`, tamamlama ve ilişkisi yeni bağlanan/değişen güncelleme yayınlar). **Sales `ActivityTouchedHandler`** (`RelatedType ∈ {lead, deal}`, diğerleri yok sayılır): `Lead/Deal.RecordActivity(at)` = `LastActivityAt = max(mevcut, at)`; idempotent (yeniden işleme/sıra dışı gelme zararsız); kayıt yoksa/silinmişse sessiz. Kuyruğa etki gecikmesi outbox yoklama süresidir (saniyeler; belgelenir, testte `OutboxProcessor` elle sürülür).
- **Mevcut veri (backfill):** (a) Sales migration'ı `UPDATE sales.leads SET owner_assigned_at = created_at WHERE owner_assigned_at IS NULL` ve `deals.owner_assigned_at = created_at`; (b) Migrator **`backfill-touches`** (`migrate` sonunda ve tek başına; idempotent `GREATEST`; host'a ait tek çapraz-şema ham SQL: `activities.activities`ten `MAX(COALESCE(completed_at, created_at)) … WHERE created_user_id IS NOT NULL AND NOT is_deleted AND related_type = 'lead'|'deal' GROUP BY tenant_id, related_id`; **ham SQL envanterine** eklenir). Kiracı kapsamı: satır `tenant_id` ile eşlenir.
- **Alan kuralları (Sales domain):** `Lead.Create/Update` ve `Deal.Create/Update` `nowUtc` alır (bugünkü `Lead.Update` içindeki `DateTime.UtcNow` `TimeProvider`a taşınır → sahte saatle test); `Create` `OwnerAssignedAt = nowUtc`; `Update` yalnız sahip değişince yazar; `AssignOwner(owner, nowUtc)` mevcut; lead dönüşümünde oluşan fırsat `OwnerAssignedAt = now`. Round-robin (`GetLastAssignedAtAsync`) `OwnerAssignedAt ?? CreatedAt` kullanmaya devam eder (backfill sonrası eşdeğer).

### Kullanıcı tanımlı kuyruklar (`workspace.saved_queues`)
Ad (1–60, kiracı+sahip başına büyük/küçük harfsiz benzersiz `queue.name_taken`), `entity` (yukarıda ✓ işaretliler; `approval` değil), `filter` (DSL), isteğe bağlı `sort` (varlık beyaz listesinden), `isShared`. Limit: kişi başına özel ≤ 25, kiracıda paylaşımlı ≤ 50 (`queue.limit_reached` 409; ayarlanır `Workspace:Queues:*`). Oluşturma/güncelleme sırasında süzgeç doğrulanır (`queue.filter_invalid`) ve **çağıranın varlığın okuma izni + kapı modülü açık** olması gerekir (aksi `403 forbidden` / `403 plan.module_disabled`). Paylaşımlı kuyruk, varlığın okuma iznine sahip herkese listelenir (izni olmayana **görünmez**, kimlikle `404 not_found`); `@me` her izleyici için kendi kimliğine çözülür. Özel kuyruk yalnız sahibine görünür (başkasınınki kimlikle `404`); sahibi pasif üyeyse özel kuyruğu kimseye görünmez, paylaşımlı kalır. Kuyruk anahtarı `saved-<guid>`.

### Sayaçlar, kapsam ve gecikme
- **Sayaç:** `SELECT count(*) FROM (… LIMIT cap+1)`; `cap = Workspace:Counts:Cap` (1000) → `capped: true` (arayüz "999+"). Aktivite ve talep kuyruklarında ikinci sayaç `overdueCount`: aktivite `schedule < now` (görev `dueAt`, toplantı/arama `startAt`; `now = TimeProvider`, **anlık** karşılaştırma), talep `slaState = breached`. Önbellek anahtarı `wq:{tenantId}:{userId}:{queueKey}` (kayıtlı kuyruk anahtarı süzgeç özetini de içerir, güncelleme eskiyi geçersiz kılar), `Workspace:Counts:CacheSeconds` = **30** (testte 0); yazma sonrası **açık geçersiz kılma yok** (yalnız TTL; arayüz mutasyon sonrası kendi sorgusunu geçersiz kılar, sunucu önbelleği ≤ 30 sn bayat kalabilir → belgelenir). Sayaç sağlayıcı zaman aşımı 2 sn: `count: null, error: "timeout"`.
- **`scope=todayOverdue` ("Bugün ve Geciken")** yalnız `task/meeting/call` kuyruklarında: `status = open` **ve** `schedule < @tomorrow` (kiracı günü sonu, dışlayıcı); tarihsiz görev kapsam dışıdır (genel listede sonda). Diğer varlıkta `400 validation` (`errors.scope`).
- **Gecikme gösterimi:** öğe `isOverdue` ise `late: { days, minutes }` sunucuda hesaplanır: `minutes = ⌊(now − at)/1 dk⌋`, `days` = **kiracı takviminde** yerel tarih farkı (`today − yerel(at)`; aynı gün geçmiş saat için 0). İstemci `days ≥ 1` → "N gün geç", aksi `minutes ≥ 60` → "N saat geç", aksi "N dk geç". Fırsat için `at = closingDate` (yalnız `days`, `minutes` yok sayılır); talep için `at` = ilk yanıt yapılmadıysa `firstResponseDueAt`, aksi `dueAt`.
- **Kuyruk sayfası veri yolu:** liste her zaman canlı (önbelleksiz), sayfalı; sıra varlığın beyaz listesinden (`sort`), aksi kuyruğun varsayılanı; her zaman `id` ile kararlı. Aktivite satırında tamamlama mevcut `POST /activities/{id}/complete` ile.

## HTTP kontratı

Hepsi `/api/v1`; `[Authorize]`; kiracı token'daki `tid`'dendir (URL'de yok). Yetki tabloları §İzinler. Doğrulama yetkiden önce çalışır (M2 kuralı).

### `GET /search?q&types&limit&page`
`types` virgülle (`account,contact,lead,deal,quote,order,case,campaign,product,activity,file`), verilmezse tümü; `limit` 1–25 (varsayılan 5); `page` ≥ 1 ve **yalnız tam bir tür** seçiliyken `> 1` olabilir (aksi `validation`, `errors.page`). Bilinmeyen tür `validation` (`errors.types`; tür adları sabit, sızıntı değil). İzin/plan nedeniyle elenen tür **hata değil**: yanıtta yoktur; hiçbiri kalmazsa `groups: []`. Yanıt `Cache-Control: no-store`.
```json
{ "query": "acme",
  "groups": [ { "type": "account", "hasMore": true, "items": [ { "id": "…", "title": "Acme A.Ş.", "subtitle": "Bilişim", "url": "/app/accounts/…", "highlight": { "title": [[0, 4]] } } ] },
              { "type": "deal", "hasMore": false, "items": [ { "id": "…", "title": "Acme yıllık lisans", "subtitle": "Acme A.Ş. · Teklif", "url": "/app/deals/…", "highlight": { "title": [[0, 4]] } } ] } ],
  "unavailable": [ { "type": "case", "reason": "timeout" } ],
  "tookMs": 41 }
```
Boş gruplar yazılmaz; `unavailable` boşsa yazılmaz; grup sırası sabit (yukarıdaki tür sırası).

### `GET /shell/summary`
`{ "asOf": "…", "badges": { "workQueue": { "count": 6, "capped": false }, "approvals": { "count": 2 }, "cases": { "count": 1 } } }`. Rozet yalnız çağıranın izni ve planı varsa yazılır (`workQueue` ← `crm.activities.read`; `cases` ← `crm.cases.read` + `service`; `approvals` ← `workflows` açık). Sayaç önbelleğini paylaşır.

### İş Kuyruğu (`/work-queues`)
- `GET /work-queues` → `{ "items": [ { "key": "my-leads", "kind": "system", "entity": "lead", "module": "sales", "listed": true, "supportsTodayScope": false, "badge?": "workQueue" }, { "key": "saved-…", "kind": "saved", "id": "…", "name": "Ankara'daki A sınıfı", "entity": "lead", "isShared": true, "ownerName": "Mert Kaya", "canEdit": false, "filter": { "v": 1, "conditions": [ … ] }, "sort?": "-createdAt" } ] }` — çağıranın varlığın okuma izni + planda açık modülü olan, `listed` sistem kuyrukları ve görebildiği kayıtlı kuyruklar (sabit sıra: sistem kuyrukları tanım sırasıyla, sonra paylaşımlılar, sonra özeller; ad artan).
- `GET /work-queues/counts?keys=a,b,c` (yok = hepsi) → `{ "asOf": "…", "items": [ { "key": "tasks-mine", "count": 31, "overdueCount": 6, "capped": false }, { "key": "cases-sla-breached", "count": null, "error": "timeout" } ] }`. İzni/planı olmayan anahtar sessizce **yer almaz**; hiç var olmayan anahtar `validation` (`errors.keys`); ≤ 40 anahtar.
- `GET /work-queues/{key}/items?page&pageSize&scope&sort` (`scope`: `all` varsayılan | `todayOverdue`) → `{ items, page, pageSize, totalCount, totalCapped, asOf }`; `totalCount` `Workspace:Counts:Cap`'te (1000) kesilir (`totalCapped`). İzin yok: sistem anahtarı `403 forbidden`, başkasının özel kayıtlı kuyruğu/bilinmeyen anahtar `404 not_found`; kapalı modül `403 plan.module_disabled`. Öğe (ortak biçim):
  ```json
  { "id": "…", "entity": "task", "title": "Teklifi gönder", "subtitle": "Acme A.Ş.", "url": "/app/activities", "status": "open", "priority": "high",
    "ownerUserId": "…", "ownerName": "Mert Kaya", "at": { "kind": "due", "value": "2026-09-14T08:00:00Z" }, "isOverdue": true, "late": { "days": 6, "minutes": 8640 } }
  ```
  `at.kind` ∈ `due|start|closing|assigned|slaDue|created`; fırsatta ek `amount`, `currency`; `url` kaydın detay sayfası (aktivitede `/app/activities`, `subtitle` ilişkili kayıt adı — okuma izni yoksa `***`, M3/L2 kuralı); `approval` öğesi `/app/approvals`.
- `GET /work-queues/entities` → varlık katalogu (yukarıdaki tablo: `entity, module, userDefinable, fields: [ { name, type, ops[], values?[] } ], sortFields[], virtualFields[]`), yalnız çağıranın okuyabildiği ve planda açık varlıklar; `FilterBuilder` bunu kullanır.
- `POST /work-queues/saved` `{ name*, entity*, filter*, sort?, isShared? }` → **201** kuyruk tanımı (yukarıdaki biçim; `Location`); `PUT /work-queues/saved/{id}` aynı gövde → 204 (tam değiştirme; `entity` **değişmez**: farklıysa `validation`; `xmin` çakışması `general.concurrency_conflict` 409); `DELETE /work-queues/saved/{id}` → 204. Yalnız sahibi (paylaşımlıda sahibi veya `org.settings.manage`) değiştirir/siler; `isShared = true` yapmak `org.settings.manage` ister (aksi `403 forbidden`); başkasının özel kuyruğu `404`.
