# Milestone 9C — Satış belgeleri ve envanter: belge alan paritesi, Fatura, Fiyat Listesi, Tedarikçi, Satın Alma Emri, arama penceresi (plan + HTTP kontratı)

PRD: [zoho-crm-klonu.prd.md](../../.claude/prds/zoho-crm-klonu.prd.md) · Analiz: `docs/analysis/zoho-ekran-analizi.md` ("Envanter ve satış belgeleri", M9C satırı, ekran görüntüleri 19–28: Fiyat Listesi, Teklif, Sipariş, Satış Fırsatı Seç penceresi, Satın Alma Emri, Fatura, Tedarikçi) · Kararlar: [kararlar.md](../architecture/kararlar.md) · Önceki: [M6A](m6a-ticaret.md) (Commerce, toplam hesabı, numara sayacı, dönüşüm), [M7](m7-saas-hazirlik.md) (plan/limit/imha/kullanım), [M8C](m8c-dosya-ekleri.md) (ek hedefleri), [M8D](m8d-ozel-alanlar.md) (özel alanlar) · Pano kartı: `C-M9C` (önerilen dal `m9/inventory`; bağımlılık: M8C/M8D merge). Biçim kuralları M2–M8 ile aynı: taban yol `/api/v1`, JSON camelCase, enum'lar camelCase string, `null` alanlar yazılmaz, hatalar ProblemDetails + `code` (+ `args`, doğrulamada `errors`), sayfalı liste `{ items, page, pageSize, totalCount }` (`page` 1'den, `pageSize` varsayılan 25 / en çok 100), `sort` = `alan` veya `-alan` (bilinmeyen alan yok sayılır, her zaman `Id` ile kararlı), `q` = `ILIKE` + kaçışlı parametre. **Çıktı:** (1) Teklif ve satış siparişi Zoho formlarıyla alan paritesine gelir: faturalama/teslimat adresi blokları, nakliye, **yuvarlama** (toplama dahil), şartlar/açıklama, sipariş alanları (müşteri satın alma emri no, gider vergisi, satış komisyonu, bekliyor, son tarih), teklif aşaması "Müzakere". (3) **Fiyat listesi**: kalem fiyatını listeden çözer (sunucu tarafı), firma varsayılanı. (4) **Tedarikçi** ve (5) **Satın Alma Emri** (`PO-2026-0001`, tedarikçi tarafı fiyatlarla). (6) Tüm formlarda yeniden kullanılabilir **arama penceresi** (tablo görünümü + `+ Yeni …` ile pencerede hızlı oluşturma). Muhasebe/e-fatura/PDF/stok yoktur (kapsam dışı listesi sonda).

## Belge alan paritesi (teklif, sipariş; fatura ve PO'da aynı bloklar)

### Adres bloğu (`billingAddress`, `shippingAddress`)
`{ "street": "Açık adres", "building": "Daire / Ev No / Bina / Apartman adı", "city", "state" (eyalet/il), "postalCode", "country" }` — hepsi isteğe bağlı metin (`street` ≤ 200; diğerleri ≤ 100; kırpılır). Tüm alanlar boşsa blok `null` saklanır (Sales `Address.Normalize` deseni) ve yanıtta yazılmaz. Tam değiştirme kuralı: PUT'ta gönderilmeyen blok temizlenir. **Koordinat (enlem/boylam) yok** (kapsam dışı). Saklama: **düz kolonlar** `billing_street, billing_building, billing_city, billing_state, billing_postal_code, billing_country` ve `shipping_*` (Sales'in "denetim alan bazında fark üretsin" kararı; `Ignore(x => x.BillingAddress)` deseni). Adres değer nesnesi Commerce'in kendi `DocumentAddress`'idir (Sales `Address`'i ile alan adları uyumlu, `building` ek). **"Adres Kopyala" yalnız web davranışıdır** (sunucu iki bloğu bağımsız saklar; kopyalama kuralı yok).

### Toplam hesabı (M6A ile aynı yuvarlama; `DocumentTotals` genişler)
Kalem formülleri (`lineSubtotal`, `lineDiscount`, `lineTax`, `lineTotal`) ve `MidpointRounding.AwayFromZero`, 2 ondalık, kalem bazında yuvarlama **aynen** korunur. Yeni:
```
subtotal, discountTotal, taxTotal         (M6A ile aynı)
adjustment                                (istekten, 2 ondalık, doğrulanmış)
grandTotal = Σ lineTotal + adjustment     (= subtotal − discountTotal + taxTotal + adjustment)
```
`DocumentAmounts(Subtotal, DiscountTotal, TaxTotal, Adjustment, GrandTotal)`; `Sum(lines, adjustment = 0m)`. Değişmez güncellenir: **`grandTotal == Σ lineTotal + adjustment`** (M6A testindeki eski değişmez adjustment=0 için aynen geçerli). Saklama: `adjustment decimal(18,2) NOT NULL DEFAULT 0`. `commerce.total_too_large` kontrolü `grandTotal`'ı yuvarlama dahil sınar. **Ek referans vektörleri** (backend `DocumentTotals` birim testi ve web `computeTotals` testi aynı tabloyu kullanır; belge {1,3} = M6A: subtotal 85.22, discountTotal 6.00, taxTotal 15.34, Σ lineTotal 94.56):
| # | Belge | adjustment | Beklenen |
|---|---|---|---|
| A1 | {1,3} | −0.56 | grandTotal **94.00** |
| A2 | {1,3} | +0.44 | grandTotal **95.00** |
| A3 | {1,3} | −94.56 | grandTotal **0.00** (geçerli) |
| A4 | {1,3} | −94.57 | reddedilir `validation.adjustment_negative_total` |
| A5 | {1,3} | 0.005 | reddedilir `validation.decimals` (3 ondalık; yuvarlanmaz) |
| A6 | kalem #1 tek başına (64.76) | −0.76 | grandTotal **64.00**; KDV/iskonto yeniden hesaplanmaz |
| A7 | kalemsiz | 0.01 | reddedilir `validation.adjustment_requires_lines`; adjustment 0 → toplamlar 0 |
| A8 | {1,3} | 1.000.000.000,01 | reddedilir (üst sınır) |
Web'de **"Yuvarla" düğmesi** (yalnız istemci): `adjustment = round(grandTotalKalemler) − grandTotalKalemler` (yarım yukarı; 94.56 → +0.44, 94.50 → +0.50, 94.49 → −0.49). `commerce-totals.ts` BigInt ölçekli tamsayıya **işaretli** dönüştürücü ekler (mevcut `toScaledInt` negatifi 0 yapar; adjustment için ayrı `toSignedMinor`); yeni bağımlılık yok.

### Teklif aşaması (Müzakere) — durum kümesi genişler
Saklanan durumlar `draft|sent|negotiation|accepted|rejected` (+ türetilen `expired`). Zoho eşlemesi: Taslak=`draft`, Teslim Edildi/Gönderildi=`sent`, **Müzakere=`negotiation`**, Onaylandı/Kapatıldı-Kazanıldı=`accepted`, Kapatıldı-Kaybedildi=`rejected`; "Beklemede (On Hold)" kapsam dışı.
| Eylem | Nereden | Nereye | Not |
|---|---|---|---|
| `negotiate` (yeni) | `sent` (süresi dolmamış) | `negotiation` | tanımsız → `quote.invalid_transition` 409 |
| `accept`, `reject` | `sent` **veya** `negotiation` | `accepted` / `rejected` | süre dolumu kuralı aynı (`accept` dolmuşsa `quote.expired`) |
| `revert` | `sent`, `negotiation`, `rejected` (etkin `expired` dahil) | `draft` | |
| `extend` | `sent`, `negotiation` (etkin `expired` dahil) | aynı | |
Türetilmiş `expired`: `status ∈ {sent, negotiation}` **ve** `validUntil < bugün` (tek `QuoteStatusExpression` güncellenir). Rapor `byStatus` sabit sırası: `draft, sent, negotiation, accepted, rejected, expired`; `conversionRate` paydası: taslak olmayan tümü (`sent+negotiation+accepted+rejected+expired`). `POST /quotes/{id}/negotiate` → 204 (`crm.quotes.write`). Diğer uç/kural M6A ile aynı.

### Sipariş durum kümesi
Değişmez `draft|confirmed|fulfilled|cancelled` (Zoho Oluşturuldu/Onaylandı/Teslim Edildi/İptal Edildi ile 1:1). **Yeni kural:** aktif (iptal edilmemiş, silinmemiş) faturası olan sipariş `cancel` edilemez → **409 `order.has_active_invoice`** (önce fatura iptal edilir).

### Yeni alanların `PUT` semantiği, dönüşüm ve göç
- `PUT /quotes|orders/{id}` tam değiştirme: gönderilmeyen yeni isteğe bağlı alanlar (adres, nakliye, `customerPoNumber`, `dueDate`, `exciseTax`, `salesCommission`, `pending`, `priceBookId`) temizlenir, `adjustment` gönderilmezse **0**'a döner (M6A "tam değiştirme" kuralı; yeni web tüm alanları gönderir).
- **Teklif → sipariş kopyalama** (`ConvertQuoteHandler`, aynı transaction): kopyalanır: `carrier`, `billingAddress`, `shippingAddress`, `adjustment`, `priceBookId` (+ M6A'nın kopyaladıkları, kalem kopyası, M8D özel alan eşlemesi). **Kopyalanmaz** (siparişe özgü): `customerPoNumber`, `dueDate`, `exciseTax`, `salesCommission`, `pending` → `null`. Toplamlar aynı `DocumentTotals` ile yeniden hesaplanır (adjustment dahil) → `grandTotal` tekliften **birebir**.
- **Göç (mevcut satırlar):** `quotes`, `sales_orders` migration'ı yalnız sütun ekler: adres/`carrier`/`priceBookId`/yeni sipariş alanları `NULL`; `adjustment NOT NULL DEFAULT 0` → mevcut `grand_total` değerleri **değişmez** (0 ile toplam aynı); yeniden hesaplama/yazma yok; `custom` sütunları M8D migration'ındadır. Eski saklı durumlar geçerli kalır (`negotiation` yeni değerdir; sütun `varchar(20)` — sığar).
- **Yanıt DTO'ları:** `QuoteDto`/`OrderDto`: `adjustment` (`taxTotal` ile `grandTotal` arasında, her zaman yazılır), `carrier?`, `billingAddress?`, `shippingAddress?`, `priceBookId?`, `priceBookName?`; `OrderDto` ek: `customerPoNumber?`, `dueDate?`, `exciseTax?`, `salesCommission?`, `pending?`, `invoiceId?`, `invoiceNumber?` (türetilir: iptal edilmemiş fatura). Özet satırları değişmez (yalnız `invoiceId?` sipariş özetine).

## Kalem fiyatı çözümü (ortak kalem motoru)
`LineRequest.unitPrice` **isteğe bağlı** olur (`decimal?`; geriye uyumlu — mevcut istemciler hep gönderir). Kalem `discountPercent`/`taxRate` davranışı değişmez (varsayılan 0).
| Durum | Sonuç |
|---|---|
| `unitPrice` verilmiş | **Override**: verilen değer esastır (≥0, ≤1e9, ≤4 ondalık); fiyat listesi çözümü yapılmaz |
| `unitPrice` yok, `productId` var, teklif/sipariş/fatura | belgenin `priceBookId`'si varsa liste çözümü, yoksa/girdi yoksa **ürün katalog fiyatı** |
| `unitPrice` yok, `productId` var, **PO** | `product.purchasePrice`; `null` ise `validation` (`errors["lines[i].unitPrice"]` = `validation.line_price_unresolvable`) |
| `unitPrice` yok, `productId` yok | `validation` (`errors["lines[i].unitPrice"]` = `validation.line_unit_price_required`) |
Çözüm **yazma anında bir kez** yapılır ve kalemde **anlık görüntü** saklanır (sonradan liste/ürün fiyatı değişse belge değişmez; M6A ürün anlık görüntüsü kuralı). Çözülen fiyat `decimal(18,4)` kuralına uyar. Çözücü Application'da `IPriceResolver` (tek sınıf; `POST /pricebooks/{id}/resolve` ve yazma yolu aynı kodu kullanır → web önizlemesi ile sunucu sonucu aynı).

## Fiyat listeleri `/pricebooks`
Alanlar: `name*` (≤200), `ownerUserId` (belge sahip kuralı: verilmezse çağıran; `owner.not_member` 400), `isActive` (varsayılan true), `pricingModel*` (`perProduct|flat`), `adjustmentPercent?` (yalnız `flat`: **zorunlu**, −99.99…1000.00, ≤2 ondalık; `perProduct`'ta verilirse `validation`), `currency` (ISO-4217, varsayılan `TRY`), `validFrom?`, `validTo?` (gün; `validTo ≥ validFrom`), `description?` (≤2000). **Değişmez:** `pricingModel`, `currency` (girdi/belgeler bağlı olduğundan) — farklı değerle PUT → **409 `pricebook.model_immutable`** (`args.property`).
- `name` kiracıda benzersiz, büyük/küçük harf duyarsız, silinmemişler arasında: `(tenant_id, name_normalized) WHERE is_deleted = false` → **409 `pricebook.name_taken`**.
- **Etkinlik** (türetilir, kiracı "bugün"ü): `isEffective = isActive && (validFrom ≤ bugün|null) && (validTo ≥ bugün|null)`. Yeni belgede/güncellemede seçilen liste **etkin ve belge para birimiyle aynı** olmalıdır: `validation` `errors.priceBookId` (`validation.price_book_inactive` / `validation.price_book_currency`); mevcut (değişmeyen) bağ geçerliliğini yitirse belge etkilenmez.
- Uçlar: `GET /pricebooks?q&isActive&currency&effective&ownerUserId&sort&page&pageSize` (`q`: ad + açıklama; `sort`: `name` (varsayılan artan), `createdAt`, `validTo` (boş her yönde sonda)), `GET /pricebooks/{id}`, `POST /pricebooks` → 201 + `Location` + gövde, `PUT /pricebooks/{id}` → 204 (tam değiştirme), `DELETE /pricebooks/{id}` → 204 (yumuşak; girdiler ve firma varsayılanları aynı transaction'da silinir; belgeler `priceBookId`yi korur, ad boş döner).
- Yanıt: `{ id, name, ownerUserId, ownerName, isActive, pricingModel, adjustmentPercent?, currency, validFrom?, validTo?, isEffective, description?, entryCount, createdAt, updatedAt? }`.

### Girdiler (yalnız `perProduct`)
`commerce.price_book_entries (tenant_id, price_book_id, product_id, unit_price decimal(18,4))`, benzersiz `(tenant_id, price_book_id, product_id)`. Ürün kiracıda var, silinmemiş ve **ürün para birimi = liste para birimi** olmalı (`validation` `errors.productId` `validation.entry_currency_mismatch`); pasif ürün için girdi yazılabilir. Liste başına **en çok 2.000 girdi** (`422 pricebook.entry_limit`). `flat` listede girdi ucu → **409 `pricebook.model_mismatch`**.
- `GET /pricebooks/{id}/entries?q&page&pageSize&sort` → `{ items: [ { productId, productName, productCode?, catalogPrice, unitPrice, updatedAt } ], … }` (`q` ürün adı/kodu; `sort`: `productName` (varsayılan), `unitPrice`, `updatedAt`); silinmiş ürünün girdisi silinmiş ürünle birlikte kalkar (ürün silme aynı transaction'da girdileri siler).
- `PUT /pricebooks/{id}/entries/{productId}` `{ unitPrice }` → 204 (ekle/güncelle, idempotent; `unitPrice` ≥0, ≤1e9, ≤4 ondalık), `DELETE /pricebooks/{id}/entries/{productId}` → 204 (yoksa 204).
- `PriceBookEntry` `IAuditLogged` (fiyat değişimi denetlenir; `GET /audit?entityType=PriceBookEntry&entityId=<girdi kimliği>`); girdi yazımı başlığın `updatedAt`ini ilerletir.

### Fiyat çözümü `POST /pricebooks/{id}/resolve` (`crm.pricebooks.read`)
İstek `{ "productIds": ["…"] }` (1–100, tekil). Yanıt `{ "items": [ { "productId", "unitPrice", "source": "entry|flat|catalog" } ] }` (istek sırası; bulunamayan/silinmiş/başka kiracı ürün **listede yok**; yanıt kiracı-içidir). Kural: `perProduct` → girdi varsa `entry`, yoksa `catalog`; `flat` → `Round4(catalogPrice × (1 + adjustmentPercent / 100))`, `MidpointRounding.AwayFromZero`, 4 ondalık, `source = flat`; liste **etkin değilse** `409 pricebook.not_effective`. Liste para birimi ≠ ürün para birimi ise ürün `catalog` kaynağıyla döner (belge kuralı zaten uyuşmayan ürünü reddeder). **Referans vektörleri** (`flat`): 19.99 @ −10 → **17.9910**; 10.10 @ −33.33 → **6.7337** (6.73367); 0.0001 @ +50 → **0.0002** (0.00015 yarım yukarı); 100.00 @ +5.25 → **105.2500**. `perProduct`: girdi 12.50, katalog 19.99 → `entry` 12.5000; girdisiz → `catalog` 19.9900.

### Firma varsayılan listesi
`commerce.account_price_books (tenant_id, account_id, price_book_id)`, benzersiz `(tenant_id, account_id)` (`ITenantEntity`). `PUT /pricebooks/accounts/{accountId}/default` `{ priceBookId }` → 204 (`crm.pricebooks.write`; firma `IRecordLookup` ile yok/silinmiş/başka kiracı → **404 `commerce.related_not_found`**; liste yok → 404 `not_found`), `GET /pricebooks/accounts/{accountId}/default` → 200 `{ priceBookId, priceBookName, isEffective }` veya **204** (varsayılan yok; `crm.pricebooks.read`), `DELETE …/default` → 204. **Sunucu belgeye otomatik uygulamaz:** yalnız web, belge editöründe firma seçilince (ve `crm.pricebooks.read` varsa) **etkin** varsayılanı `priceBookId` olarak önerir; kullanıcı değiştirir/temizler. Fırsat düzeyinde varsayılan yok.

## Faturalar `/invoices`
Fatura `SalesDocument`'tir (firma zorunlu). Alanlar: `subject*` (≤200), `accountId*`, `contactId?`, `dealId?`, `ownerUserId`, `currency`, `invoiceDate` (varsayılan bugün, kiracı saati), `dueDate?`, `customerPoNumber?`, `exciseTax?`, `salesCommission?`, `carrier?`, adresler, `adjustment`, `priceBookId?`, `terms?`, `notes?`, `lines[]` (M6A kalem kuralları + fiyat çözümü), `customFields?` (M8D). Bağlı kayıt kuralları (`commerce.related_not_found`, `contact_account_mismatch`, `deal_account_mismatch`) teklif/sipariş ile aynıdır. `orderId`/`orderNumber` yalnız **siparişten dönüşümle** dolar, gövdede kabul edilmez, değişmez.
- **Numara:** `INV-{yıl}-{sıra:D4}` (kind `invoice`, M6A sayaç kuralları aynen: kiracı saat diliminde yıl, `document_counters` atomik `INSERT … ON CONFLICT`, aynı transaction, `(tenant_id, number)` benzersiz, silinmiş numara yeniden kullanılmaz). `DocumentNumberFormat`'a `InvoicePrefix = "INV"`.

### Durum makinesi (saklanan `draft|sent|cancelled`; etkin durum türetilir)
| Eylem | Nereden | Nereye | Kurallar |
|---|---|---|---|
| `send` | `draft` | `sent` | ≥1 kalem (`invoice.no_lines` 422); `dueDate` doluysa ≥ `invoiceDate`; `sentAt`; `InvoiceSent` event |
| `revert` | `sent` (`paidAmount = 0`) | `draft` | tahsilat varsa **409 `invoice.has_payments`**; `sentAt` temizlenir |
| `cancel` `{ reason? }` | `draft`, `sent` | `cancelled` | tahsilat varsa 409 `invoice.has_payments` (önce tahsilatlar silinir); `cancelledAt`, `cancelReason`; `InvoiceCancelled`; sipariş yeniden faturalanabilir hâle gelir |
| `PUT`, `DELETE` | yalnız `draft` | — | aksi `invoice.not_editable` 409 |
`cancelled` uçtur. Tanımsız geçiş → **`invoice.invalid_transition` 409** (`from`, `to`).
**Etkin durum (`status` yanıtta/filtrede/raporda; tek `InvoiceStatusExpression`, kiracı "bugün"ü; zamanlanmış iş yok):** stored `draft`/`cancelled` → aynen. Stored `sent` için öncelik sırası: (1) `paidAmount ≥ grandTotal` → **`paid`** (sıfır tutarlı gönderilmiş fatura da `paid`); (2) `dueDate < bugün` (vade günü **geçmemiş** sayılır) → **`overdue`**; (3) `paidAmount > 0` → **`partiallyPaid`**; (4) **`sent`**. Yani vadesi geçmiş kısmi ödemeli fatura `overdue` görünür (`balanceAmount` gösterir). Zoho "Onaylandı" adımı yoktur (onay M4 iş akışıdır).

### Tahsilat (`invoice_payments`)
`{ id, amount, paidOn, method?, reference?, notes?, recordedByUserId, recordedAt }` — `amount` > 0, ≤2 ondalık; `paidOn` gün, **≤ bugün** (`validation.paid_in_future`) ve **≥ `invoiceDate`** (`validation.paid_before_invoice`); `method` ∈ `cash|bankTransfer|card|cheque|other` (isteğe bağlı); `reference` ≤100; `notes` ≤500.
- `POST /invoices/{id}/payments` → 201 + tahsilat gövdesi. Yalnız `sent` faturaya (etkin `sent|partiallyPaid|overdue`); `draft`/`cancelled`/`paid` faturaya **409 `invoice.not_payable`**; `amount > balanceAmount` → **422 `invoice.payment_exceeds_balance`** (`args`: `balance`). Aynı transaction'da faturanın `paid_amount`ı güncellenir; tamamı ödendiyse `InvoicePaid` event (bakiyenin 0'a ilk inişinde; tahsilat silinip yeniden ödenirse yeniden yayınlanır, tüketici idempotent olmalıdır).
- `DELETE /invoices/{id}/payments/{paymentId}` → 204 (yanlış giriş düzeltmesi; yalnız `cancelled` olmayan fatura; `paid_amount` geri düşer, `paid → partiallyPaid/sent/overdue` türetimi otomatik). Tahsilat güncelleme ucu yoktur (sil + yeniden gir; YAGNI).
- **Eşzamanlılık:** fatura `xmin` belirteci taşır; iki eşzamanlı tahsilat aynı bakiyeyi görürse ikincisi **409 `commerce.concurrent_update`** (aşırı ödeme asla oluşmaz).
- `paid_amount` = Σ tahsilat (denormalize; testte her yazma sonrası eşitlik değişmezi).

### Siparişten dönüşüm `POST /orders/{id}/invoice` (tek transaction)
Gövde isteğe bağlı `{ "invoiceDate": "YYYY-MM-DD", "dueDate": "YYYY-MM-DD" }` (boşsa `invoiceDate = bugün`, `dueDate = null`; varsayılan vade süresi kapsam dışı — M9J). İzin `crm.orders.read` + `crm.invoices.write`. Akış: sipariş yüklenir (yok → 404); durum `confirmed` veya `fulfilled` değilse **409 `order.not_invoiceable`**; iptal edilmemiş fatura varsa **409 `order.already_invoiced`**; firma/kişi/fırsat yeniden doğrulanır (`commerce.related_not_found`); aynı savepoint/transaction'da: `invoice` sayacından numara, fatura `draft` (kopya: `subject`, `accountId`, `contactId`, `dealId`, `ownerUserId`, `currency`, `terms`, `notes`, `carrier`, adresler, `adjustment`, `priceBookId`, `customerPoNumber`, `exciseTax`, `salesCommission`; **kopyalanmaz:** `pending`, `dueDate` (istekten)), **kalemler yeni kimliklerle kopyalanır ve `DocumentTotals` ile yeniden hesaplanır** (tutarlar siparişten birebir), M8D `MapAsync("order","invoice")`, `InvoiceCreated` (`source: "order"`) outbox → **201** + `Location: /api/v1/invoices/{id}` + fatura detayı. **Çift dönüşüm engeli (kesin):** `invoices (tenant_id, order_id) WHERE order_id IS NOT NULL AND is_deleted = false AND status <> 'Cancelled'` **benzersiz indeks** (`ux_invoices_tenant_order`; saklanan enum adı `Cancelled`); eşzamanlı ikinci dönüşüm indeks ihlaliyle düşer, savepoint geri alınır (sayaç dahil), `order.already_invoiced` 409; asla iki aktif fatura, asla numara boşluğu. `draft` faturayı silmek veya faturayı iptal etmek siparişi yeniden faturalanabilir yapar. Herhangi bir adımda hata → hiçbir şey kalıcı olmaz. Sipariş `fulfilled` olsa da faturalanabilir; fatura siparişin durumunu **değiştirmez**.

## Rapor `GET /reports/commerce/summary` (`crm.reports.read`) — toplamsal genişleme
Aralık/saat/varsayılan kuralları M6A ile aynı. Mevcut `quotes` (bölüm `byStatus` +`negotiation`) ve `orders` **değişmez** (`grandTotal` artık `adjustment` içerir). Yeni bölümler:
```json
"invoices": { "totalCount": 5, "totalAmount": 41000.00, "paidAmount": 15000.00, "outstandingAmount": 26000.00, "overdueCount": 1, "overdueAmount": 6000.00,
  "byStatus": [ { "status": "draft", "count": 1, "amount": 3000.00 }, { "status": "sent", "count": 1, "amount": 8000.00 }, { "status": "partiallyPaid", "count": 1, "amount": 12000.00 },
                { "status": "paid", "count": 1, "amount": 12000.00 }, { "status": "overdue", "count": 1, "amount": 6000.00 }, { "status": "cancelled", "count": 0, "amount": 0 } ] },
"purchaseOrders": { "totalCount": 3, "totalAmount": 22000.00,
  "byStatus": [ { "status": "draft", "count": 1, "amount": 2000.00 }, { "status": "confirmed", "count": 1, "amount": 10000.00 }, { "status": "received", "count": 1, "amount": 10000.00 }, { "status": "cancelled", "count": 0, "amount": 0 } ] }
```
Faturalar `invoiceDate` (yerel gün), PO'lar `poDate` aralığında; `byStatus` sabit sırada, **etkin durum bugüne göre**, `amount = grandTotal` toplamı. `totalCount/totalAmount` **iptaller hariç** (taslaklar dahil). `paidAmount` = iptal edilmemiş faturaların `paid_amount` toplamı; `outstandingAmount` = etkin `sent|partiallyPaid|overdue` faturaların `grandTotal − paidAmount` toplamı; `overdueCount`/`overdueAmount` (= bakiye toplamı) etkin `overdue` için. `currencies` fatura/PO para birimlerini de içerir (tutarlar para birimine bakmadan toplanır; M6A sınırlaması, kur M9J).
