# Milestone 7 — SaaS hazırlığı: planlar/limitler, kiracı yaşam döngüsü, platform konsolu, kullanım ölçümü, onboarding (plan + HTTP kontratı)

PRD: [zoho-crm-klonu.prd.md](../../.claude/prds/zoho-crm-klonu.prd.md) (Milestone 7) · Kararlar: [kararlar.md](../architecture/kararlar.md) (K1, K2, K13, K17) · Önceki: [M5](m5-pilot-yayin.md), [M6A](m6a-ticaret.md), [M6B](m6b-servis.md), [M6C](m6c-pazarlama.md), güvenlik: [hardening-report.md](../security/hardening-report.md) · Pano kartı: `C-M7` (dal `m7/saas`). Biçim kuralları M2–M6 ile aynı: taban yol `/api/v1`, JSON camelCase, enum'lar camelCase/snake string (aşağıda belirtildiği gibi), `null` alanlar yazılmaz, hatalar ProblemDetails + `code` (+ `args`, doğrulamada `errors`), sayfalı liste `{ items, page, pageSize, totalCount }` (`page` 1'den, `pageSize` varsayılan 25 / en çok 100), `sort` = `alan` veya `-alan` (bilinmeyen alan yok sayılır, her zaman kimlikle kararlı), `q` = `ILIKE` + kaçışlı parametre. Gün alanları `YYYY-MM-DD`, zaman damgaları ISO 8601 UTC.

**Çıktı:** Ürün ilk olarak grup içinde (tek plan: `internal`, limitsiz) kullanılmaya devam eder; SaaS'a açıldığında dış müşteri kiracıları (1) planla açılır (kullanıcı/kayıt limitleri, modül bayrakları, deneme süresi), (2) limit/askı/deneme bitişi sunucuda **tek ortak mekanizmayla** zorlanır, (3) platform yöneticisi konsoldan organizasyonları görür, plan/deneme değiştirir, askıya alır/yeniden açar, KVKK'ya uygun silme talebi başlatır, (4) günlük kullanım anlık görüntüleri finans için CSV olarak dışa aktarılır, (5) yeni organizasyon kendi kendine kayıtla (yalnız `Registration:Mode=open`) varsayılan deneme planında açılır ve ana sayfada ilk kurulum kontrol listesi görür. **Ödeme sağlayıcısı, fatura, tahsilat yoktur** (kapsam dışı); PRD'deki "faturalama" maddesi yalnızca ölçüm + dışa aktarma kancasıyla karşılanır, "süreç stüdyosu" bu karta dahil değildir.

## Kiracı yaşam döngüsü

Saklanan durum `tenant_accounts.status`: `active | suspended | pending_deletion | deleted`. **Etkin durum** okuma anında saf fonksiyonla (`Shared.Contracts.Entitlements.TenantLifecycle.Evaluate(status, suspensionMode, trialEndsAt, now)`) türetilir — zamanlanmış iş yoktur (M6A'daki `expired` teklif deseni; sahte saatle test edilir):

| Saklanan | Koşul | Etkin durum (`status`) | Erişim (`accessLevel`) |
|---|---|---|---|
| `deleted` | — | `deleted` | `none` |
| `pending_deletion` | — | `pending_deletion` | `none` |
| `suspended` | `mode = blocked` | `suspended` | `none` |
| `suspended` | `mode = readOnly` | `suspended` | `readOnly` |
| `active` | `trial_ends_at` var ve `now >= trial_ends_at` | `trial_expired` | `readOnly` |
| `active` | `trial_ends_at` var ve `now < trial_ends_at` | `trial` | `full` |
| `active` | deneme yok | `active` | `full` |

`suspended` denemenin bitmesinden önceliklidir. JSON değerleri: `status` ∈ `trial|active|trial_expired|suspended|pending_deletion|deleted`, `accessLevel` ∈ `full|readOnly|none`.

**Deneme günü:** API `trialEndsOn` (gün, dahil) alır; sunucu `trial_ends_at` = "`trialEndsOn`'dan sonraki günün başlangıcı (kiracı saat diliminde) UTC" olarak saklar (`TenantCalendar`; Europe/Istanbul'da `2026-12-31` → `2026-12-31T21:00:00Z`; `now >= trial_ends_at` ise deneme bitmiştir). Kiracı saat dilimi sonradan değişirse saklı an yeniden hesaplanmaz (kabul edilen sınırlama). `trialEndsOn` bugünden (kiracı saati) önce olamaz (`validation`, `errors.trialEndsOn`); anında bitirmek için askıya alınır.

**Geçişler** (Platform komutları; tanımsız her geçiş `platform.invalid_transition` 409, `from`/`to` argümanlı): `active → suspended` (suspend), `suspended → active` (reactivate; deneme bitmişse etkin durum `trial_expired` kalır — plan/deneme ayrıca düzeltilir), `active|suspended → pending_deletion` (deletion-request; önceki durum saklanır), `pending_deletion → önceki durum` (yalnız `scheduled` talepte iptal), `pending_deletion → deleted` (yalnız imha işi). **Sistem kiracısı** (`is_system`, platform yöneticisinin işletim organizasyonu) askıya alınamaz/silinemez/planı değiştirilemez: `platform.system_tenant_protected` 422.

## Planlar ve limitler

### Plan tanımı (`Platform:Plans`, `platform.plans`)
```json
"Platform": {
  "Signup":       { "PlanCode": "starter" },
  "Provisioning": { "DefaultPlanCode": "internal" },
  "Plans": [
    { "code": "internal",   "name": "İç kullanım", "sortOrder": 0, "trialDays": null,
      "limits": { "maxUsers": null, "maxRecords": {} },
      "modules": { "workflows": true, "commerce": true, "service": true, "marketing": true } },
    { "code": "starter",    "name": "Starter", "sortOrder": 10, "trialDays": 14,
      "limits": { "maxUsers": 5,  "maxRecords": { "sales": 5000, "activities": 10000 } },
      "modules": { "workflows": false, "commerce": false, "service": false, "marketing": false } },
    { "code": "business",   "name": "Business", "sortOrder": 20, "trialDays": 14,
      "limits": { "maxUsers": 25, "maxRecords": { "sales": 100000, "activities": 200000, "commerce": 50000, "service": 50000, "marketing": 20000, "workflows": 50 } },
      "modules": { "workflows": true, "commerce": true, "service": true, "marketing": false } },
    { "code": "enterprise", "name": "Enterprise", "sortOrder": 30, "trialDays": null,
      "limits": { "maxUsers": 250, "maxRecords": {} },
      "modules": { "workflows": true, "commerce": true, "service": true, "marketing": true } }
  ]
}
```
(Sayılar örnektir; gerçek fiyat/limit ticari karardır. Testler kendi yapılandırmasını kullanır.)

- **Modül bayrakları** yalnız `workflows | commerce | service | marketing` (kapı modülleri, `GatedModules`). `identity`, `sales`, `activities` çekirdektir, kapatılamaz; bilinmeyen anahtar Migrator'ı durdurur. Eksik anahtar = `false`.
- **Limitler:** `maxUsers` (**sert**: etkin + bekleyen davetli üyelik sayısı; pasif üyelik saymaz) ve `maxRecords.<modül>` (**yumuşak**: modülün yaşayan kayıt toplamı — Sales: hesap+kişi+lead+fırsat, Activities: aktivite, Workflows: kural, Commerce: ürün+teklif+sipariş, Service: talep, Marketing: kampanya; yumuşak silinenler sayılmaz). `null`/yok = sınırsız; `0` = o modülde yeni kayıt açılamaz. **Depolama limiti yoktur** (dosya eki/MinIO henüz yok, K16; eklenince `LimitKeys`'e yeni anahtar + reporter metriği).
- **Doğrulama (Migrator):** kod `^[a-z][a-z0-9_]{1,31}$`, limitler ≥ 0, `trialDays` 1–365 veya null, `Signup.PlanCode` ve `Provisioning.DefaultPlanCode` katalogda olmalı; hata → Migrator ≠ 0 çıkış (yayın durur). Yapılandırmadan kalkan plan `is_active = false` olur (mevcut atamalar çalışır, yeni atama `platform.plan_not_found`).

### Kiracıya özel istisna (`overrides`, `tenant_accounts.overrides jsonb`)
`{ "maxUsers": 10|null, "maxRecords": { "sales": 200000|null }, "modules": { "workflows": true } }` (hepsi isteğe bağlı, kısmi). **Etkin değer = override varsa o, yoksa plan.** `overrides.maxUsers: null` açıkça sınırsız demektir; anahtar hiç yoksa plan geçerli (JSON'da `null` ile "yok" ayrımı için `maxUsers` anahtarının varlığı esastır). Birleştirme saf fonksiyondur (`EffectiveEntitlements.Merge`), birim testli.

## Paylaşılan zorlama mekanizması (D4)

### `Shared.Contracts.Entitlements` (yeni; tam liste)
```csharp
public static class GatedModules { public const string Workflows = "workflows", Commerce = "commerce", Service = "service", Marketing = "marketing"; /* All */ }
public static class LimitKeys   { public const string Users = "users", Records = "records"; }
public enum AccessLevel { Full, ReadOnly, None }

public sealed record EntitlementSnapshot(Guid TenantId, string PlanCode, string PlanName,
    string RawStatus, string? SuspensionMode, DateTimeOffset? TrialEndsAt, DateOnly? TrialEndsOn, string TimeZone,
    IReadOnlyDictionary<string, bool> Modules, int? MaxUsers, IReadOnlyDictionary<string, int?> MaxRecords)
{ public (string Status, AccessLevel Access) Evaluate(DateTimeOffset now); }   // TenantLifecycle.Evaluate'a delege

public interface ITenantEntitlements { Task<EntitlementSnapshot> GetAsync(Guid tenantId, CancellationToken ct = default); }
public sealed record LimitDemand(string Key, string? Module, int Delta = 1);
public interface ILimitGuard { Task<Result> EnsureAsync(LimitDemand demand, CancellationToken ct = default); }   // plan.limit_exceeded (402) döner
public interface IPlanCatalog { Task<bool> IsAssignableAsync(string planCode, CancellationToken ct = default); }
```
Öznitelikler: `[ConsumesLimit(LimitKeys.Users|Records, amount = 1)]` (komut), `[NoPlanLimit("gerekçe")]` (kayıt oluşturan ama saymayan komut), `[TenantStatusExempt("gerekçe")]` (salt okunur/askıda da çalışan kullanıcı-düzeyi komut/sorgu), `[EntitlementExempt("gerekçe")]` (sistem olay işleyicisi/Conductor görevi), `[PlatformAdminOnly]` (`Shared.Contracts.Security`).
Ayrıca `Shared.Contracts.Security.IPlatformAdminVerifier { Task<bool> IsPlatformAdminAsync(Guid userId, CancellationToken ct); }` (Identity uygular: kullanıcı aktif **ve** bayrak veritabanında) ve `Shared.Contracts.Usage.IUsageReporter`, `Shared.Contracts.Retention.ITenantDataEraser` (aşağıda).
**Varsayılanlar** (`AddCrmCore`, `TryAdd`): `UnlimitedEntitlements` (her şey açık, `Full`), `AllowAllLimitGuard`, `AllowAllPlanCatalog` → Platform yüklenmemiş host/testlerde davranış değişmez. Platform modülü `services.Replace(...)` ile gerçeklerini kaydeder.

### `EntitlementBehaviour<TRequest,TResponse>` (`Shared.Infrastructure`)
Kayıt sırası: `Logging → Validation → Authorization → UnitOfWork → **Entitlement** → Caching` (yani yetki ve doğrulamadan **sonra**: yetkisiz çağıran plan bilgisi öğrenmez; UoW'den **sonra**: sert limit için açık transaction içinde kilit alınabilir). Algoritma (kiracı bağlamı yoksa — anonim auth komutları — veya sistem bağlamıysa (`UserId == null`) atlanır):
1. `[PlatformAdminOnly]` isteği → atla (platform kapsamı kiracı durumundan bağımsız).
2. `snapshot = ITenantEntitlements.GetAsync(tenant)`; `(status, access) = Evaluate(now)`.
3. `access == None` ve istek `[TenantStatusExempt]` değilse → `403 tenant.suspended` (`args.reason = status`).
4. `access == ReadOnly` ve istek `ICommand` ve `[TenantStatusExempt]` değilse → `403 tenant.suspended`.
5. `module = ModuleOf(typeof(TRequest).Assembly)`; `module ∈ GatedModules` ve `!snapshot.Modules[module]` ise → `403 plan.module_disabled` (`args.module`) — **okuma dahil** (özellik plana dahil değil).
6. Komutta her `[ConsumesLimit]` için `ILimitGuard.EnsureAsync(...)` → aşımda `402 plan.limit_exceeded` (`args`: `limit`, `module?`, `max`, `used`).

`ILimitGuard` (Platform uygular): `users` → **kesin, önbelleksiz** sayım (Identity `IUsageReporter`), sayımdan önce Identity'nin açık transaction'ında `pg_advisory_xact_lock(hashtextextended('limit:users:'||tenantId, 0))` alınır (`IModuleUnitOfWork`'e eklenen `AcquireAdvisoryLockAsync`; Platform, `Identity` modül UoW'sunu adıyla bulur) → eşzamanlı üye eklemeler kiracı başına sıraya girer, limit asla aşılmaz. `records` → `Platform:Usage:CacheSeconds` (300 sn) önbellekli sayım; **yumuşak** (önbellek süresi içinde sınır bir miktar aşılabilir, bilinçli). Sınır sonlu olmayan (`null`) limit için sayım **hiç yapılmaz** (`internal` plan sıfır ek sorgu; sonlu limitli kiracılar küçük olduğundan `COUNT` ucuz).
Maliyet: her istekte bir `HybridCache` aramasıdır (JWT'ye plan claim'i konmaz; izinlerle aynı yaklaşım). Önbellek: anahtar `ent:{tenantId}`, `Platform:Entitlements:CacheSeconds` = 30; Platform komutları aynı süreçte anında geçersiz kılar (çok kopyada diğer kopyalar ≤ 30 sn + L2 süresi bayat kalır — runbook §9.1 tablosuna satır eklenir). Ham durum önbelleklenir; **etkin durum her çağrıda `now` ile hesaplanır** (deneme bitişi önbellek süresine takılmaz).

- **`OrganizationCreated` genişler** (`Identity.Contracts`, geriye uyumlu, eski outbox satırları çözülebilsin diye tümü varsayılanlı): `+ Slug? , OrganizationOrigin Origin = signup|platform|bootstrap, PlanCode?, TrialEndsOn?`. `OrganizationProvisioner.CreateAsync` bu değerleri alır: `auth/signup` → `signup`; `POST /platform/organizations` → `platform` (+ isteğin `planCode`/`trialEndsOn`'u; `IPlanCatalog.IsAssignableAsync` ile **eşzamanlı** doğrulanır, bilinmeyen plan `400 validation` / `errors.planCode`); Migrator `create-platform-admin` → `bootstrap`. Runbook yükseltme adımı Migrator'ı zaten çalıştırır; duman testi (`smoke.sh`) "satırı olmayan kiracı yok" denetimini ekler.

## HTTP kontratı — Platform konsolu (`/platform/**`, yalnız platform yöneticisi)

Tüm uçlar: platform politikası + `[PlatformAdminOnly]`; kiracı yöneticisi (tüm izinlerle Administrator dahil) **403 `forbidden`**, anonim 401. Yanıtlarda kiracı iş verisi yoktur; yalnız hesap/plan/sayaç.

### Organizasyonlar
- `GET /platform/organizations?q&status&planCode&source&sort&page&pageSize` → sayfalı. `q`: ad + slug. `status` **etkin durum** (`trial|active|trial_expired|suspended|pending_deletion|deleted`; tek `TenantStatusExpression` liste filtresi, DTO ve sayaçta ortak kullanılır). `sort`: `name` (varsayılan artan), `createdAt`, `users` (son anlık görüntüdeki aktif kullanıcı; boşlar her iki yönde sonda), `plan`, `status`. Satır:
  ```json
  { "tenantId": "…", "name": "Acme A.Ş.", "slug": "acme", "planCode": "starter", "planName": "Starter", "source": "signup",
    "status": "trial", "accessLevel": "full", "trialEndsOn": "2026-10-04", "isSystem": false, "createdAt": "…",
    "usage": { "day": "2026-09-20", "usersActive": 3, "usersPending": 1, "records": { "sales": 340, "activities": 120 } } }
  ```
  `usage` yoksa (henüz anlık görüntü yok) yazılmaz; `records` = anlık görüntüdeki `<modül>.records` değerleri.
- `GET /platform/organizations/{tenantId}` → satır alanları + `limits` (**etkin**: `{ maxUsers?, maxRecords: {…}, modules: {…} }`), `overrides?`, `planChangedAt?`, `suspension?: { mode, reason, at }`, `deletion?: { requestId, status, requestedAt, requestedByEmail?, reason, retentionDays, scheduledFor, cancelledAt?, completedAt?, attempts, lastError? }`. Bilinmeyen kimlik `404 not_found`.
- `POST /platform/organizations` → **M5 ucu genişler**: gövdeye `planCode?`, `trialEndsOn?` (verilmezse `Platform:Provisioning:DefaultPlanCode`, denemesiz); yanıta `planCode` eklenir; `Cache-Control: no-store` kuralı aynen.

### Abonelik (plan/deneme/istisna)
- `PUT /platform/organizations/{tenantId}/subscription` `{ planCode*, trialEndsOn?, overrides? }` → **200** `{ overLimit: [ { limit: "users"|"records", module?, max, used } ] }` (kalıcı ve tam değiştirme: `trialEndsOn` yok/null = denemesiz (etkin/`active`), `overrides` yok/null = temiz). Bilinmeyen/pasif plan `404 platform.plan_not_found`; `overrides` doğrulaması (`maxUsers ≥ 0`, modül anahtarı kapı modülü olmalı, `maxRecords` anahtarları bilinen modüller) `400 validation` (`errors["overrides.maxUsers"]` …). Kiracı `pending_deletion|deleted` ise `409 platform.invalid_transition`; sistem kiracısı `422 platform.system_tenant_protected`. **Mevcut kullanım yeni limitin üstündeyse plan yine de değişir** (veri silinmez); `overLimit` bunu bildirir ve aşım giderilene kadar yeni tüketim `402 plan.limit_exceeded` alır. Değişen bir şey varsa `PlanChanged` + denetim `subscription.changed` (`details`: plan/deneme/istisna eski→yeni); değişiklik yoksa yazma yapmaz, yine 200.

### Askı ve yeniden açma
- `POST /platform/organizations/{tenantId}/suspend` `{ reason* (≤500), mode?: "readOnly"|"blocked" (varsayılan readOnly) }` → 204 (`active` değilse `409 platform.invalid_transition`; `TenantSuspended` + `organization.suspended`).
- `POST /platform/organizations/{tenantId}/reactivate` → 204 (yalnız `suspended`; `TenantReactivated` + `organization.reactivated`).

### Silme talebi (KVKK)
- `POST /platform/organizations/{tenantId}/deletion-request` `{ reason* (≤500), retentionDays? }` → **200** `{ requestId, scheduledFor }`. `retentionDays` varsayılan `Platform:Deletion:RetentionDays` (30), `[MinRetentionDays 7 .. MaxRetentionDays 90]` dışı `400 validation` (`errors.retentionDays`). Yalnız `active|suspended`; kiracı **anında** `pending_deletion` (`accessLevel none`) olur, tüm kullanıcılar dışarıda kalır. Zaten etkin talep varsa `409 platform.invalid_transition`. Olay `TenantDeletionRequested`, denetim `deletion.requested`.
- `POST /platform/organizations/{tenantId}/deletion-request/cancel` → 204 (yalnız `scheduled` talep ve `now < scheduled_for`; kiracı `previous_status`'e döner; aksi `409 platform.deletion_not_cancellable`). Denetim `deletion.cancelled`.
- İmha işi ve silinen kapsam: aşağıdaki "İmha işi" bölümü.

### Kullanım
- `GET /platform/organizations/{tenantId}/usage?from&to` (UTC günleri, dahil; varsayılan son 90 gün; aralık ≤ 400 gün, ters/aşan `400 validation`) → `{ items: [ { day, usersActive, usersPending, metrics: { "sales.accounts": 120, … } } ] }` (gün artan; anlık görüntüsü olmayan gün yok).
- `POST /platform/organizations/{tenantId}/usage/refresh` → 200 tek öğeli aynı biçim: kiracı kapsamında **canlı** sayım yapar ve bugünün anlık görüntüsünü yazar (yalnız `active|suspended|trial*`; `pending_deletion|deleted` için 409). Denetim `usage.refreshed`.
- `GET /platform/usage/export?from&to` → **CSV** (`text/csv; charset=utf-8`, UTF-8 BOM, `Content-Disposition: attachment; filename="usage-{from}-{to}.csv"`, akış halinde yazılır). `from`/`to` (UTC günü, dahil) verilmezse **önceki takvim ayı**; aralık ≤ 400 gün. Satır = (kiracı, gün) anlık görüntüsü, gün artan sonra kiracı adı; sütunlar: `day,tenantId,slug,name,planCode,status,usersActive,usersPending` + aralıktaki anlık görüntülerde geçen tüm `metrics` anahtarlarının **alfabetik birleşimi** (eksik değer boş hücre). `status` = anlık görüntü **günü** için değil dışa aktarma anındaki etkin durumdur (belgelenir). RFC 4180 kaçışı; hücre `= + - @ \t \r` ile başlıyorsa başına `'` konur (CSV formül enjeksiyonu). Denetim `usage.exported` (`from`,`to`, satır sayısı). **Faturalama kancası budur:** ileride fatura modülü bu tabloyu/CSV'yi ve `PlanChanged`/`TenantSuspended` olaylarını tüketir; M7 `BillingAccount` kavramı içermez.

- `GET /platform/plans` → `[ { code, name, description?, isActive, sortOrder, trialDays?, limits, modules, assignedCount } ]` (`sortOrder`; `assignedCount` silinmemiş hesap sayısı). Yazma ucu **yoktur** (D3).

## İmha işi (KVKK) — `TenantErasureService`

Worker `BackgroundService`, `Platform:Deletion:PollMinutes` (10) dakikada bir, `pg_try_advisory_lock` ile tek örnek. İş kuyruğu: (a) `status = scheduled` ve `scheduled_for <= now` talepleri; (b) `running`/`failed` talepler (`attempts < Platform:Deletion:MaxAttempts` = 10, üstel bekleme). Sahte saatle sürülebilir.

Akış: talep `running` (`started_at`); **imha adımları** (`ITenantDataEraser`, `Order` sırasıyla; her adım kendi transaction'ında/parçalarında, **idempotent**, tamamlanınca `erased_steps`'e adı eklenir; yeniden çalıştırma tamamlananları atlar):

| Sıra | Adım (`Name`) | Ne silinir (kiracı `T`) |
|---|---|---|
| 100 | Her modül için `TenantDataEraser<TContext>` (`AddModuleDbContext` içinde otomatik kayıtlı → yeni modül **unutulamaz**) | Modülün EF modelindeki **tüm `ITenantEntity` tabloları** (yumuşak silinenler **dahil**; `DELETE FROM "şema"."tablo" WHERE tenant_id = @t`, 10.000'lik parçalarla `ctid` döngüsü, FK bağımlılığına göre çocuk önce — EF metadata'sından topolojik sıra) + modülün `outbox_messages` ve `inbox_messages` satırları. `AuditLogEntry` hariç (aşağıda). |
| 100 (Workflows) | `WorkflowsConductorEraser` (ek `ITenantDataEraser`) | Kiracının çalışan yürütmeleri sonlandırılır ve **Conductor'daki** yürütme kayıtları `IWorkflowEngine.Remove(engineWorkflowId)` (Conductor `DELETE /api/workflow/{id}/remove`) ile silinir (girdilerde konu adı/`tenantId` kalmasın); DB satırlarından **önce** çalışır (`Order` 90). Conductor hatası adımı `failed` yapar, yeniden denenir. |
| 800 | `IdentityAccountEraser` | (a) `identity.memberships`/`roles` generic adımla gitmiştir; (b) **başka hiçbir üyeliği kalmayan** (herhangi bir kiracıda, herhangi bir durumda) ve **platform yöneticisi olmayan** hesapların `refresh_tokens` ve `users` satırları; (c) `identity.tenants` satırı. Başka kiracıda üyeliği olan hesap **kalır** (yalnız bu kiracıdaki üyeliği/rolü gider). Ham SQL ile `NOT EXISTS` (kiracı-kör bir sorgudur; envanterde listeli). |
| 900 | `AuditTenantDataEraser` (Platform) | `audit.audit_log_entries WHERE tenant_id = @t` (kişisel veri barındıran `changes` dahil). |
| 950 | `PlatformTombstone` | `usage_snapshots` (T) silinir; `tenant_accounts`: `status = deleted`, `deleted_at`, `name = '[deleted]'`, `slug = 'deleted-' + son 8 hex (UUIDv7'nin ilk bitleri zaman damgasıdır; ilk 8 hex aynı dönemde açılan kiracılarda çakışırdı)`, `overrides = null`; `platform_audit_entries.target_tenant_name` (T) `'[deleted]'` yapılır; `deletion_requests`: `status = completed`, `completed_at`, `report` (adım → tablo → silinen satır sayısı, **kişisel veri yok**). Olay `TenantErased`, denetim `deletion.completed`. |

**Bilerek silinmeyenler:** `platform_audit_entries` satırları (eylem/aktör/zaman; kiracı adı redakte), `deletion_requests` satırı (imha kanıtı), `tenant_accounts` mezar taşı, ortak (başka kiracıda üyeliği olan) hesaplar, önbellek girdileri (kiracı önekli, TTL ≤ 10 dk; ayrıca imha sonunda `tenant:{T}` etiketiyle geçersiz kılınır), **yedekler** (saklama süresi boyunca kalır — runbook §12 güncellenir; geri yükleme sonrası kural: Migrator `erase-deleted-tenants` komutu tüm mezar taşları için imhayı yeniden koşar, idempotent). Hata: adım hatası `attempts++`, `last_error` (kısaltılmış, kişisel veri içermez), `status = failed`; `MaxAttempts` sonrası `failed` kalır ve `deletion.failed` denetimi + günlük uyarısı (konsolda kırmızı). Sistem kiracısı asla imha edilmez.

- ***İmha işi (tam kapsam):*** iki kiracı (A silinecek, B kalacak) + A ile B'nin **ortak** hesabı + yalnız A'ya ait hesap + platform yöneticisi A'da üye; yedi modülde veri (yumuşak silinmiş satırlar, kalemler/yorumlar/olay satırları, outbox/inbox, denetim, Conductor yürütmeleri). Beklenti: A için **her `ITenantEntity` tablosunda** (tüm DbContext'lerin EF modelinden **yansımayla** üretilir — yeni tablo otomatik kapsanır) `count(tenant_id = A) = 0`; B'nin tablo başına satır sayıları imhadan önceki anlık görüntüyle **birebir**; ortak hesap yaşıyor ve yalnız B üyeliği kaldı; A'ya özel hesap + refresh token'ları gitti; platform yöneticisi hesabı yaşıyor; `audit_log_entries` A gitti/B duruyor; `identity.tenants` A yok/B var; mezar taşı (`deleted`, `[deleted]`, `deleted-xxxx`, `report` sayıları sıfır-olmayan ve kişisel veri içermeyen); `platform_audit_entries` satırları duruyor ama ad redakte; **idempotent** (ikinci koşu no-op, mezar taşına dokunmaz); **yarım kalma:** bir adım bir kez hata atar → `failed` + `erased_steps` ilerlemesi, sonraki turda kalan adımlarla tamamlanır ve tamamlanmışlar tekrar koşmaz; parçalı silme büyük veriyle (`ChunkSize` küçültülerek) doğru; zamanlama: `scheduled_for` öncesi dokunmaz (sahte saat), sonrasında koşar; iptal (bekleme içinde → önceki duruma döner, çalışırken/sonra `platform.deletion_not_cancellable`); `retentionDays` 7–90 sınırları; `pending_deletion` kiracı anında her uçta 403 ve girişte reddedilir; sistem kiracısı imha edilmez; Conductor sahte motoru her yürütme kimliği için `Remove` çağrısı alır; `erase-deleted-tenants` komutu geri yüklenmiş (yeniden görünen) veriyi tekrar siler.
- ***Kullanım ölçümü doğruluğu:*** her modül reporter'ı bilinen veri kümesiyle elle hesaplanmış değerleri döner (yumuşak silinen ve başka kiracı satırları **hariç**, modül toplamı = alt toplamların toplamı); kullanıcı sayısı etkin/bekleyen/pasif ayrımı; anlık görüntü işi: idempotent (aynı gün iki koşu tek satır), askıdaki dahil, `pending_deletion`/`deleted` hariç, bir kiracıda hata diğerlerini engellemez, kiracı kapsamı sızıntısı yok (A'nın sayacı B'ninkini karıştırmaz), saklama temizliği; CSV: sütun birleşimi alfabetik, boş hücre, kaçış, formül enjeksiyonu önekleme (`=cmd`, `+1`, `-1`, `@x`), varsayılan önceki ay, aralık > 400 gün 400, yalnız platform yöneticisi, `usage.exported` denetimi, büyük satır sayısı akış hâlinde.
- ***Onboarding:*** dört adımın her biri veri değişince tamamlanır, tamamlanan silinse de kalır, `workflows` kapalıyken adım yok ve `totalCount` düşer, `dismiss` sonrası sayım yapılmaz (sorgu sayacı), hepsi tamam → sayım yok, backfill'li eski kiracı `dismissed`, kayıt (signup) yolu yeni kiracı için 0/4.
- ***Kiracı izolasyonu ve platform ucu erişilemezliği (zorunlu):*** (1) **Tüm tenant izinlerine sahip Administrator token'ı ile `/api/v1/platform/**` altındaki her uç 403** (uçlar `EndpointDataSource`'tan yansımayla listelenir — yeni platform ucu otomatik kapsanır), token'sız 401; (2) **sonradan geri alınan bayrak:** platform yöneticisi token'ı alındıktan sonra hesabın bayrağı veritabanında kaldırılır → aynı token 403 (JWT'ye güvenilmez); (3) platform yöneticisi başka kiracının iş verisini **okuyamaz/yazamaz** (`GET /accounts` kendi işletim organizasyonunu döner); (4) A'nın `GET /subscription`/`onboarding`/`me` yanıtları yalnız A'yı gösterir; A yöneticisi B'nin kimliğiyle hiçbir uçta sonuç alamaz; (5) `TenantFilterBypassInventoryTests` (envanter birebir), `RequestAuthorizationTests` (üç öznitelik + ad alanı kuralları + `/platform` denetleyici politikası), Platform varlıklarının `ITenantEntity` olmaması, hiçbir modülün `Platform.*` referansı olmaması, her modülün `IUsageReporter`'ı, `Create*Command` limit kuralı, izin kataloğunda `platform.` anahtarı yokluğu; `Sense.Crm.Tests.TenantIsolation` yeni küresel varlıkları `GlobalEntities` ile bilerek kapsar.
- *Regresyon:* mevcut tüm modül testleri Platform yüklü hâlde (`internal` plan) değişmeden yeşil; `GET /me` yeni alanı yazar, eski istemci uyumu.
