# Mimari Kararlar (ADR özeti)

Kaynak: [PRD](../../.claude/prds/zoho-crm-klonu.prd.md), [mimari diyagram](mimari.webp).
Ürün Zoho CRM gibi çok kiracılı bir SaaS olarak tasarlanır; grup şirketleri ilk kiracılardır.

**K0 — Referans altyapı:** Teknoloji stack'i ve proje yapısı kardeş proje **senseik** ile aynıdır; altyapı oradan taşınır (`Sense.*` → `Sense.Crm.*`), CRM için gereksiz parçalar baştan alınmaz. Ayrıntı: [backend.md](backend.md). Aşağıdaki satırlarda senseik ile çelişen bir ifade olursa senseik deseni geçerlidir. **Mobil uygulama yok; yalnızca web.**

| # | Konu | Karar | Gerekçe |
|---|---|---|---|
| K1 | Kiracı modeli | Kiracı = organizasyon (şirket). Bir kullanıcı hesabı birden çok organizasyona üye olabilir ve aralarında geçiş yapar (Zoho'daki "org switch"). | Grup çalışanları birden çok şirkette çalışabilir; SaaS müşterileri de aynı modelle açılır. |
| K2 | Veri ayrımı | Tek PostgreSQL veritabanı, satır bazlı ayrım: her kiracı verisinde `TenantId` kolonu, EF Core global query filter zorunlu. Kiracı dışı sorgu yalnızca açıkça `IgnoreQueryFilters` ile ve platform yöneticisi yetkisiyle. İleri aşamada PostgreSQL RLS ikinci savunma hattı olarak eklenir. | Kullanıcı talebi (tek DB, satır bazlı). |
| K3 | Kapasite hedefi | "250+" belirsiz; tasarım hedefi: 1.000 kiracı, 10.000 kullanıcı, büyük kiracıda 10M kayıt. Tüm kiracı indeksleri `(TenantId, ...)` ile başlar. | Her iki yorumu da (250 şirket / 250 kullanıcı) rahat karşılar. |
| K4 | Grup konsolidasyonu | MVP'de yok. Sonra "organizasyon grubu" kavramı + grup raporları için salt-okur çapraz kiracı görünümü. | Satır bazlı modelde güvenli çapraz erişim ayrı tasarım ister. |
| K5 | Uygulama mimarisi | .NET 10 modüler monolit, senseik düzeni: modül başına `Sense.Crm.Modules.<X>.{Domain,Application,Contracts,Infrastructure,Api}`, ayrı şema + DbContext + migration; modüller yalnızca `*.Contracts` üzerinden konuşur. Kendi CQRS dispatcher'ı + pipeline behaviour'ları, MVC controller'lar, `/api/v1` URL versiyonlama. Host'lar: `Sense.Crm.Api`, `Sense.Crm.Worker` (outbox), `Sense.Crm.Migrator`. | Diyagram: CRM API katmanı + bağımsız ölçeklenen worker'lar. Erken microservice karmaşasından kaçınır. |
| K6 | Kimlik doğrulama | Senseik Identity modülünden: e-posta + parola (PBKDF2, kilitleme), RS256 JWT access token (~15 dk) + döner refresh token (family ile yeniden kullanım tespiti). Token organizasyon bağlamını (`tid`) taşır. MFA, e-posta daveti, AD/LDAP/OIDC SSO sonraki aşama. | Kanıtlanmış kod; SaaS'ta her müşteri AD'ye sahip değil. |
| K7 | Yetkilendirme | RBAC: organizasyon başına roller, rollere izin anahtarları (`crm.leads.read` vb.). Sistem rolleri (Yönetici, Standart) her yeni organizasyona tohumlanır. Kayıt sahipliği bazlı görünürlük (Zoho "profile + role hierarchy") sonraki aşama. | Diyagram: RBAC/ABAC. |
| K8 | Çok dillilik | Web: i18next, `tr` ve `en` başlangıç, JSON kaynak dosyaları. API: hata kodları sabit anahtar döner, metin çevirisi istemcide. Kullanıcı başına dil tercihi. | Kullanıcı talebi (çok dilli). |
| K9 | Workflow motoru | Conductor OSS (Orkes'in açık kaynak çekirdeği), Docker ile kendi veri merkezinde. CRM API workflow başlatır; worker'lar görevleri çeker. | Diyagram; lisans maliyeti yok, yurt içi barındırılabilir. |
| K10 | Olaylar | Modül içi domain event'ler; modüller arası integration event'ler transactional outbox ile. | Tutarlılık; worker'lara güvenilir iletim. |
| K11 | Veri katmanı | PostgreSQL (ana), Redis (önbellek), MinIO (S3 uyumlu nesne depolama, yurt içi), Elasticsearch/OpenSearch arama (2. aşama). | Diyagram; tamamı self-host edilebilir. |
| K12 | Web | Senseik web stack'i: pnpm workspace (`web`, `packages/*`), React + Vite + TypeScript, Mantine 9 + Tailwind v4 (yalnızca yerleşim), react-router v7, paylaşılan `packages/api-client`. | Ekip bilgisi, tek UI dili. |
| K13 | Barındırma | Yurt içi, kendi veri merkezi. Geliştirmede Docker Compose; üretimde Kubernetes (Helm) hedefi. KVKK: kişisel veri alanları işaretlenir, denetim kaydı zorunlu. | Kullanıcı talebi. |
| K14 | Denetim | Senseik `AuditLogInterceptor`: denetlenen varlıklarda değişiklik kaydı (kim, ne, ne zaman, alan farkı) modülün kendi şemasındaki `audit_log_entries` tablosuna, aynı transaction'da, kiracı bazlı. | Diyagram: Audit & Compliance. |
| K16 | Baştan alınmayanlar | Hangfire, SignalR, e-posta/bildirim, MinIO, dışa aktarma (PDF/Excel), AI/MCP, gözlemlenebilirlik yığını (Seq/Jaeger/Grafana/Sentry), RabbitMQ, veri kapsamı (DataScope), taklit (impersonation), API anahtarları, MFA. İhtiyaç doğduğu milestone'da senseik'ten eklenir. | Kullanıcı talebi: gereksizler baştan dahil edilmesin. |
| K15 | Test | xUnit + Testcontainers (gerçek PostgreSQL), web için Vitest. Kiracı izolasyonu için zorunlu entegrasyon testleri. | PRD riski: kiracılar arası sızıntı = 0. |
| K17 | Pilot dağıtımı (M5) | Kurum içi pilot: tek sunucuda Docker Compose (`deploy/docker-compose.prod.yml`); yalnız web portu yayınlanır, backend ağı dışarıya kapalı (`internal`); TLS harici vekilde; sırlar `.env` + Docker secret dosyaları (varsayılan parola yok); API/Worker en az yetkili `crm_app` DB rolüyle, DDL yalnız migrator'da. Herkese açık kayıt Production'da varsayılan **kapalı** (`Registration:Mode`); organizasyonu platform yöneticisi açar (`POST /platform/organizations`), ilk yönetici Migrator komutuyla. RPO/RTO önerisi ≤ 4 sa / ≤ 4 sa (onay bekliyor). | Kurum içi kullanımda kendi kendine kayıt istenmez; veri merkezinden çıkış olmaması (KVKK) ağ düzeyinde zorlanır. Ayrıntı: [runbook](../operations/runbook.md), [m5-pilot-yayin](../plan/m5-pilot-yayin.md). |
| K18 | SaaS hazırlığı (M7) | **Plan + yaşam döngüsü + salt okunur:** planlar yapılandırma güdümlü (`Platform:Plans` → `platform.plans`, plan arayüzü yok); limitler/modül bayrakları tek `EntitlementBehaviour` + paylaşılan `ITenantEntitlements` ile zorlanır (olay veri yolu, Conductor yoklayıcısı ve oturum üretimi aynı kaynağı kullanır). Kiracı durumu yalnız `platform.tenant_accounts`te tutulur; etkin durum (deneme/askı) okuma anında saf fonksiyonla türetilir. **Deneme bitişi ve askı (varsayılan) salt okunurdur** (okuma serbest, kullanıcı kaynaklı yazma `403 tenant.suspended`); `blocked` askı ve silme bekleyen tam engeldir. Sert limit: kullanıcı sayısı (istişari kilit), yumuşak: kayıt sayısı (önbellekli). Platform yöneticisi bir hesap bayrağıdır (kiracı izni değil; her istekte veritabanından doğrulanır), kiracı verisini okuyamaz. KVKK: silme talebi → bekleme (7–90 gün) → kalıcı imha + mezar taşı; yedekler temizlenmez. Ödeme/fatura/tahsilat kapsam dışıdır (yalnız ölçüm + CSV kancası). | Müşteri verisine erişimi (dışa aktarma/karar) kesmek gereksiz sertlik; güvenlik olayı/silme için tam engel ayrıca vardır. Tek zorlama noktası dağınık `if`leri ve unutulan modülleri önler; "silme ≠ imha" açığı kapanır. |
| K19 | Entegrasyonlar (M8B) | **Giden webhook + API anahtarı + OpenAPI** ([m8b-entegrasyonlar](../plan/m8b-entegrasyonlar.md) D1–D14): yeni modül `Integrations` (plan kapı modülü `integrations`, sınırlar `maxWebhooks`/`maxApiKeys`); webhook'lar yalnız outbox integration event'lerinden beslenir, PII'siz açık-izin-listeli zarfla, `X-Crm-Signature: t=…,v1=HMAC-SHA256` imzasıyla, en az bir kez teslim (8 deneme, üstel geri çekilme, ölü mektup, otomatik pasifleştirme). **Dış çağrıyı yalnız Worker yapar**; SSRF: çöz → doğrula (kalıcı/varsayılan engel IP listeleri, gömülü IPv4) → doğrulanan IP'ye sabitle, yönlendirme yok, ikinci katman egress proxy IP ACL'i; `backend` ağı `internal` kalır, çıkış yalnız `egress` profilindeki dns+proxy'den ve **varsayılan kapalı**. Sır AES-256-GCM (AAD bağlı) şifreli, bir kez gösterilir, grace'li döndürme. API anahtarı ayrı kimlik doğrulama şeması (`Bearer crmk_<kiracı>_<önek>_<sır>`, yalnız SHA-256 özeti saklanır), oluşturana bağlı (act-as-creator), kapsam = `crm.*` ∖ `crm.approvals.decide`, kapsam ⊆ oluşturan ve her istekte kapsam ∩ oluşturanın o anki izinleri; `[AnyAuthenticatedUser]`/`[PlatformAdminOnly]` anahtara kapalı (tek istisna `GetCurrentApiKeyQuery`); anahtar başına ayrı hız kovaları. | Modül sınırı (K5) ve kapı modülü mekanizması (K18) yeni koda gerek bırakmadan tüm istek/işleyicileri plana bağlar; SSRF ve yetki yükseltme tek katmanda hataya bağlı kalmasın diye çok katmanlıdır; KVKK: PII'siz zarf, kiracı sorumlu, egress kapalı varsayılan (K13/K17). Ayrıntı: [backend.md](backend.md) §23, [runbook](../operations/runbook.md) §15. |
| K20 | Gözlemlenebilirlik (C-OPS1) | **Yalnız metrikler** (iz ve merkezî günlük yığını yok). Api ve Worker OpenTelemetry **metrik** SDK'sı ile (`OpenTelemetry.Extensions.Hosting` + `OpenTelemetry.Exporter.Prometheus.AspNetCore`; ihraççı hâlâ `beta`, sürümler `packages.lock.json`'da kilitli) framework'ün yerleşik Meter'larını (ASP.NET Core RED, Kestrel, hız sınırlayıcı, HttpClient, `System.Runtime`, EF Core, Npgsql) ve tek `Sense.Crm` Meter'ındaki iş/işletim metriklerini yayınlar (`CrmMetrics`, `Shared.Contracts`: outbox bekleyen/ölü/gecikme, workflow yürütmeleri, Conductor yoklama/görev sonuçları, plan zorlaması reddi, giriş hataları/kilitlenme, refresh yeniden kullanımı, KVKK silme hattı). **Etiketler yalnız düşük kardinaliteli** (`module|status|reason|outcome|task_type|plan|step|background_job`; HTTP için yol *şablonu*); kiracı/kullanıcı/kayıt kimliği, e-posta, IP **asla** etiket olmaz (kaydediciler serbest etiket almaz; test kapısı çıktıdaki etiket adlarını denetler; KVKK + seri patlaması). Uç nokta **kapalı varsayılır** (`Observability:Metrics:Enabled`), açılınca ana porttan **ayrı bir dinleyicide** (Api 9464, Worker 9465; ana hattan bağımsız küçük Kestrel; yalnız `GET /metrics`) sunulur: nginx'e/ana porta bağlanmaz, hiçbir port yayınlanmaz; koruma **ağ yalıtımı (`internal` backend ağı) + isteğe bağlı bearer belirteç** (Docker secret dosyası). Yığın `deploy/docker-compose.observability.yml` **overlay**'idir (varsayılan `up`'ın parçası değil): Prometheus (saklama: 30 gün / 5 GB), Grafana (**yalnız `127.0.0.1`**, veri kaynağı + 5 pano + alarm kuralları dosyadan; yönetici parolası Docker secret, varsayılan yok), postgres-exporter (salt-okur `crm_monitor`/`pg_monitor` rolü), isteğe bağlı node-exporter/cAdvisor (`host-metrics` profili); imajlar sürüm etiketiyle sabit; Prometheus ve exporter'lar yalnız `internal` ağlarda (çıkış yok), Grafana'nın loopback portu için ayrıca bir köprü ağı vardır (Docker internal ağdan port yayınlayamaz; Grafana dışarı çağırmayacak şekilde ayarlı, ağ düzeyinde çıkış engeli işletme sorumluluğunda). Alarmlar Prometheus'ta değerlendirilir, **bildirim kanalı yok** (çıkışsız yığında SMTP rölesi kurum politikasıdır); her alarmın runbook başlığı vardır. K16'nın "gözlemlenebilirlik yığını" maddesini **yalnız metrik/Prometheus/Grafana için** kaldırır; Seq/Jaeger/Sentry/Loki hâlâ kapsam dışıdır. | Kurum içi pilotta "çalışıyor mu, neden yavaş, iş birikiyor mu, saldırı var mı" sorularına kanıtla cevap gerekir; metrik en ucuz ve en az sızdıran sinyaldir (günlükten farklı olarak kişisel veri taşımaz). Ayrı dinleyici + iç ağ, yanlış nginx/vekil yapılandırmasının metrikleri dışarı sızdırmasını yapısal olarak önler; overlay varsayılan dağıtımı ve saldırı yüzeyini değiştirmez. Ayrıntı: [runbook §16](../operations/runbook.md), [backend §23](backend.md). |
